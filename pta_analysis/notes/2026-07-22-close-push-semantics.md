# 7/22 close_push 业务语义踩坑记录

## 触发场景

用户在飞书问 L3 展开行 Call 端"存多" -2753 是什么意思,我自己对话里两次答错
(把"卖方平仓"误读成"原多头平多头仓"→又把"卖方"读成"动词")。用户两次拍脸后
彻底去查代码+飞书原文,定位到 NAT_DIR 语义层面我有结构性误读。

## 业务链路(澄清后)

`close_push`(OI↓ IV↑)在飞书 §2.3.1 单合约性质判定表业务含义是
"**卖方平仓(对冲买压/卖压释放)**":

1. OI↓ = 总持仓减少(双方中有人主动平仓)
2. IV↑ = 这次 buy-to-close 推升隐波(证实是真实买盘,不是报价跳动)
3. 平值/OTM_slight 位置 Gamma 风险最大 → 义务仓(short option seller)最想平的位置
4. **卖方 buy-to-close** = 解除这个 strike 上的"对冲锚"
   - Call 卖方原本 Delta=-0.5~-1,价格涨就要买期货对冲
   - 平仓后,这部分"右侧加速器"失效 → **对冲买压释放 → 标的更易上行**
   - Put 卖方原本 Delta=+0.5~+1,价格跌就要卖期货对冲
   - 平仓后,这部分"左侧加速器"失效 → **对冲卖压释放 → 标的更易下行**
5. NAT_DIR 映射:
   - NAT_DIR_CALL[close_push] = '看多' ← 业务含义是"反向加速看多"(对标的有利的副作用)
   - NAT_DIR_PUT[close_push] = '看空' ← 业务含义是"反向加速看空"

## 我之前两轮的错误

### 第一轮
我误说"老多头在主动平多头仓" → 严重事实错误(根本不是多头方在平)。
代码 NAT_DIR_CALL 注释"平 Call 多头"误导我 → 我顺着字面意思推,没看飞书
§2.3.1 性质判定表写得很清楚"卖方平仓"。

### 第二轮
我说"卖方"是动词"卖出多头持仓" → 部分对但模糊。**真正的"卖方"是名词,
指的是 short option seller(义务仓持有者)**,他们 buy-to-close 自己原本
卖出的 Call/Put 来解除 Gamma 风险。不是动词。

## 业务方读研报的潜在误读

研报 L3 展开表格列头 "新多/新空/新中性/存多/存空" 直接套用 NAT_DIR 的方向词,
业务方看到 "存多: -2753" 会自然读成"看多方向的存量持仓减少"(以为是看多
平仓 → 标的微调小跌方向)。**实际业务含义是"原 Call 卖方在对冲压力解除
→ 对冲买压减弱 → 标的更易上行"**。这两层语义差异没在研报里说清。

## 我踩这个坑的根本原因

1. **代码注释有歧义**:
   - compute_weighted_nature.py L48:"Call close_push = 平 Call 多头"
   - 这个"平 Call 多头"读起来像"平掉 Call 多头仓" → 误以为是多头方平仓
   - **实际上是"OTM/ATM Call 的卖方(卖 Call 的空头方)在对冲多头 Delta
     暴露时,buy-to-close 拆除"Call 多头方向的 Delta 中和仓位"**
2. **没有先读飞书 §2.3.1 性质判定表就回答** —— 表里写得很清楚"卖方平仓"
3. **没有被反跑偏 grep 抓到**:没去 `grep "close_push.*=.*\[" /tmp/feishu*.txt`
   确认业务含义就先凭印象答

## 自我反省(7/22 沉淀)

- **讲 L3 算法前必跑**:grep code + read_file 飞书原文(§2.3.1 性质判定表/方向映射表)
- **不要凭 nature 名字的字面意思推**:`close_push` 字面是"close + push",
  也不是"O TM Call 卖方对冲压力释放"—— 字面意思误导了自己
- **NAT_DIR 的"看多/看空"是分类标签,不是业务定义** —— 看到 "close_push → 看多"
  要立刻追问"这个看多对应什么业务机理"而不是接受标签
- **研报口径 ≠ 算法口径**:研报"存多/存空"是按 NAT_DIR 方向词直接展示,但
  业务方理解成"主动看多/看空"的持仓变化 —— 这是**显示层 vs 算法层**语义
  不匹配的典型案例
